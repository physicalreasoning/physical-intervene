# Amendment 2026-11-26: the format check when the positive control is not run

**Stage.** After freeze 1 (commit 117ae28, `frozen/design.json` sha256
`f55415351f971d7726a81708ef2b3bd0508e6f12b30c7916dad564224999d140`), before the pilot. DESIGN.md
is not changed.

**What existed at this point.** No training, validation, pilot or test data had been generated and
no model had been trained on any split after Phase 0. The only data and models were Phase 0's
(smoke data, stand-ins, and networks trained on smoke data, never scored on interventions). No
gate, intervention error or result of any kind existed.

**What was found, and the evidence.** DESIGN.md (*Controls*) says that if no p in the grid fits
V*, the positive control is not run and a G1 *fail* reads *inconclusive: test not shown sensitive*.
`build_primary` handles this, but the format check `check_conformance` required `mlp-shortcut`
among the controls in every result, so in that case `score.py` would flag a format error and exit
with failure although every number and reading were right. A new test (build a result with no
`mlp-shortcut` and check it against the format) found it on 2026-11-26.

**The fix.** `check_conformance` accepts a result without `mlp-shortcut` only when the positive
control pair is reported as not tested. No rule, threshold or reading changes.

**How the amendment is checked.** So that the frozen hashes can admit this fix and nothing else,
`seal.check_frozen` now accepts a hashed file that differs from freeze 1 only if an amendment in
`frozen/amendments.json` records its new sha256; freeze 2 records the sha256 of
`frozen/amendments.json`. That needs changes to `seal.py` and `scripts/freeze.py`, which this
amendment also records.
