# Amendment 2026-11-26 (2): the scorer cannot load a checkpoint written by training

**Stage.** After freeze 1 (commit 117ae28, `frozen/design.json` sha256
`f55415351f971d7726a81708ef2b3bd0508e6f12b30c7916dad564224999d140`) and the amendment
`2026-11-26.md`, during the pilot: after the pilot grid, during the pilot confirmation. DESIGN.md is
not changed.

**What existed at this point.**

- Data in `data/main/` (sha256 in `data/main/manifest.json`): the training, validation and pilot
  episodes, the 200 pilot states with their history, and the two policy-mean files. No test
  states.
- The pilot grid: 108 runs on pilot data (96, and 6 more for each of `gru` and `contact_wm`, whose
  grids were extended), and `results/pilot/settings.json` (sha256
  `7eccc67dee8e0925502e74a9b127136cc1607dfd51fe563aed6af6d17bb3a5f6`). The grid uses validation loss
  only.
- The pilot confirmation's 6 control runs on pilot data (`mlp-shortcut` seeds 451, 462, 473;
  `mlp-twin` seeds 231, 242, 253), trained but not scored.
- No main run, no `results/pilot/confirmation.json`, no gate, no result. No intervention error of
  any model had been computed, including the two controls.

**What was found, and the evidence.** `pilot.py confirm` trained the 6 control runs and then failed
when the scorer loaded the first checkpoint:

```
_pickle.UnpicklingError: Weights only load failed ...
Unsupported global: GLOBAL torch.torch_version.TorchVersion
```

`train.py` stores `"torch": torch.__version__` in each checkpoint's metadata. That value is a
`torch.torch_version.TorchVersion` (a subclass of `str`), and `scoring.load_checkpoint_for_scoring`
loads with `torch.load(..., weights_only=True)`, which refuses every class not on torch's
allowlist. Phase 0 did not meet this: its stand-ins store `str(torch.__version__)`, the dry run of
the confirmation stops before scoring, and the checkpoint test loads with `weights_only=False`. The
same loader serves `score.py`, so every checkpoint of the main runs would have failed in the same
way at scoring. Loading all 1,092 confirmation checkpoints with `TorchVersion` allowed, and nothing
else, succeeded, so this class is the only obstacle. A new test (train a model for 10 updates and
load it through `load_checkpoint_for_scoring`) failed before the fix and passes after it.

**The fix.** `load_checkpoint_for_scoring` loads inside
`torch.serialization.safe_globals([TorchVersion])`: the safe loader stays on and admits this one
string class only. Training, the checkpoints already written and every rule are unchanged; no run is
retrained.
