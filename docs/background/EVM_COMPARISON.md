# Comparison with evm-intervene

**Background, not frozen.** This file explains or compares; it does not define the test and is
not part of freeze 1 or 2. Where it and [DESIGN.md](../DESIGN.md) differ, DESIGN.md governs.

## Shared terms

"evm-intervene" below means what its code computes (`scripts/run_experiment.py`,
`src/evm_intervene/metrics.py`); where its code and its `docs/DESIGN.md` differ, the code is
used here.

| Term | evm-intervene | here |
| --- | --- | --- |
| L_obs, observational validation loss | one-step std-MSE on held-out observational swaps | one-step std-MSE on held-out observational transitions |
| E_int, intervention error | std-MSE on the hard regimes (II cliff + III cascade) | std-MSE on the push stratum (contact that moves the box; see *Interventions* in DESIGN.md) |
| easy stratum | regime I, in-tick | no contact, and graze (contact that barely moves the box) |
| physical-unit error | log-price RMSE, bps | box corner RMSE, mm |
| Δ_int, the issue's *consistency gap* | E_int(challenger) − E_int(reference) at matched checkpoints; JSON `matched_cliff_gap.gap` | same quantity; JSON `matched_push_gap.gap` |
| std-MSE | `TargetScaler`, training-split std, per-dimension floors | same; floors in this task's units |
| match screen | \|L_a − L_b\| / min(L_a, L_b) ≤ 0.05 | same |
| bootstrap, p-value, Holm | 5,000 replicates over held-out states (one per archive checkpoint, 54); p = min(1, 2(min(#≤0, #≥0)+1)/5,001); Holm across all pairs tested, screened or not | same; held-out simulator states (1,000) |
| E_int aggregation | per-transition loss averaged over seeds, then over all hard transitions, pooled across states | same |
| G0 | simulator matches on-chain price; every model beats `copy` on L_obs (best checkpoints) | bit-exact replay; every main model beats `copy` (matched and best checkpoints); sanity control (see G0) |
| G1 pass rule | screened pair with Holm p < 0.05, CI excludes zero, relative gap ≥ 20% | same; *not testable* if no pair passes the screen |
| G2 reading | Spearman ρ(L_obs, E_int) over best checkpoints; decoupled if point ρ < 0.50 | same; refuted if point ρ ≥ 0.80 |

## Deliberate differences

These are design choices, not oversights. Each is reported so the two G1s can be read correctly
side by side.

| Item | evm-intervene | here | Why |
| --- | --- | --- | --- |
| Pairs in G1 | each of 3 challengers against one anchor, `conservation_wm` | all 6 pairs of the 4 main architectures, including the structured `contact_wm` | `contact_wm` plays `conservation_wm`'s structural role but is not made the anchor: testing all pairs keeps the pairs of general-purpose models in G1, and no model sets the matching target alone |
| Relative gap | Δ / E_int(reference), reference = the anchor | Δ / E_int(reference), reference = the pair member with the lower E_int | with no anchor, this fixes the reference so Δ ≥ 0 and the formula is evm's |
| Loss matching | anchor uses its best checkpoint; other models stop at the checkpoint closest to the anchor's 5-seed mean best L_obs | every run trains its full budget at a constant learning rate, then takes the checkpoint closest to V* = 1.1 × the largest per-architecture median best L_obs; the gap is also reported at other shared levels and at best checkpoints | no model is favoured by being the anchor, V* is reachable by all, and the extra levels show whether a gap is only a difference in learning speed |
| Bootstrap resamples | clusters only | clusters and, independently per architecture, the seeds (evm's version is reported too) | stops a seed-to-seed difference from passing as an architecture difference |
| Seeds | 5: 11, 22, 33, 44, 55 | 10 at medium width (11 to 110), the first five being evm's; 5 (11 to 55) at small and large widths; twins 121 to 220 | resampling 5 seeds understates seed noise by about a third; see *Why 10 seeds* in [RATIONALE.md](RATIONALE.md) |
| G0.1 | simulator vs on-chain price, median error < 0.05 bps | bit-exact replay of the full integration state | the simulator is the ground truth here, so exactness is checkable |
| Controls | a synthetic check, `scripts/run_positive_control.py`: it reruns `mlp_direct` vs `conservation_wm` on synthetic pools generated by its exact simulator and reports whether the gap's interval is above zero; it is not one of its gates. Its Mainnet runs have no control pairs | a positive control (a pair with a gap built in), negative controls (pairs with no real difference) and a sanity control, all on the test states, through the G1 procedure (see *Controls* in DESIGN.md) | a G1 *fail* means something only if G1 is shown able to detect a gap, and a G1 *pass* only if it is shown not to find one where there is none |
